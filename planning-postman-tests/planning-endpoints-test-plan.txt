PLANNING MODULE - POSTMAN TEST PLAN

Location:
- Base route: /planning
- Auth: all endpoints below require the auth token middleware
- Wrapper: expect the usual API wrapper, with HTTP status matching the case and a business payload containing status=success on successful calls

PREREQUISITES

1. Run the SQL scripts before testing this module.
   Minimum order:
   - migrations/014_planning_socle.sql
   - migrations/015_planning_employee_documents.sql
   - migrations/016_planning_shifts_core.sql
   - migrations/017_planning_time_entries.sql
   - migrations/018_planning_leave_and_swaps.sql

2. Prepare Postman variables:
   - {{baseUrl}}
   - {{token}}
   - {{employeeId}}
   - {{employeeId2}}
   - {{uploadFileKey}}
   - {{documentId}}
   - {{weekId}}
   - {{weekId2}}

   - {{leaveRequestId}}

3. Common headers for JSON requests:
   - Authorization: Bearer {{token}}
